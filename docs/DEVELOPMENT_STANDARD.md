# 一小时开发与验收标准

## 最新用户纠正（2026-10-25，优先于下方历史轮次）

- 后续实现和真实/浏览器验收由当前主智能体统一完成。链接的另一会话仅作只读参考，不再向其委派开发或验收；按AGENTS保留独立只读审查子智能体，不以实现者自评替代。
- 优先打通真实输入、搜索、原文读取、两道审查、带出处答案的闭环。“张飞是谁”须实际执行验证，不能只交离线测试；未完成的服务不能包装成证据不足，真正没查清也不能捏造确定答案。
- 撤下产品里的通用原理、无关示例、提示词式说明和论文入口。“为什么这样查”仅在对应问题已有真实事件时显示，以本次问题、实际查询目的、来源判断、已核验答案和真实引文解释判断。空白/未执行阶段不编解释。下文旧的论文入口展示要求由本条取代；论文仍可作为开发依据保留在文档中。
- 原子事实不因“是谁”扩展成字、籍贯、年代、谥号的大复合主张；先回答实际问到的身份。保持证据门槛、供应商、3200默认单次输出预算、最多6搜索/300秒调度预算，禁止隐藏扩容重试。
- 原文阅读分批，每次至多4页、总计至多8页；为反证/补查保留阅读份额，新查询优先于仅域名启发的一手候选。候选发现可看搜索线索，但确定答案仍必须有本次已读原文与两道独立审查；审查批次至多2来源。

此前轮次截止未被重置。下面历史时间盒及原始记录保留；最新实际结果见ACCEPTANCE.md顶部。

后续增量修复必须同时遵守 [半小时修复方案与验收标准](HALF_HOUR_REPAIR.md)。该方案保留原有证据门槛、供应商和视觉风格，并规定本轮截止与验收场景。

版本：2026-10-25，用户批准的最小改动交付。实施起点：12:50（Asia/Shanghai）。功能冻结：13:33；最终截止：13:50。后续修改若超出本轮范围，另行记录，不自动扩大任务。

## 1. 目标和不可退让项

保留现有页面布局、游戏档案风格与五张工作流卡片。搜索产出有依据的回答，角色卡展示本次真实过程。外部服务成功率不作保证；证据不足不等于错误，引用逐字匹配不等于语义正确。

1. 明确事实最多三个原子主张，保留用户原句及对象、时间、版本、条件；不将首次引入扩大成持续至今的保证。
2. 开放问答先检索，最多一次候选事实提取，最多三个带来源候选主张；随后进行原有独立来源适用性审查和片段支持度审查。未核验候选不能当作答案。
3. 答案分为已查明、尚未查明。确定事实绑定已通过门槛的主张和证据；PARTIAL 展示支持内容与限制，不自动解释为事实部分成立。
4. 最多六次搜索、300秒调度预算；针对具体缺口自动补查且查询去重。只有影响调查方向的实质歧义才询问用户。
5. 保留当前单次模型调用上限，不增加同请求自动重试；后续超时不得清除先前已核实结果。服务失败与材料不足分开显示。
6. 搜索摘要只能作线索；确定结论仍要求适用来源、原文匹配、完整支持或直接反例，以及原有来源门槛。不因权威身份自动认为内容支持，不将旧/新版本差异自动当矛盾。
7. 新接口字段增量兼容；旧报告正常加载，不新增服务端接口、数据库、供应商、多模型框架或训练流程。

## 2. 五张卡片、六个角色

| 卡片 | 角色 | 实际记录 |
|---|---|---|
| 拆解问题 | 领案员·罗盘，青绿/地图 | 原问题、主张、范围 |
| 寻找证据 | 寻踪员·小蓝，蓝/放大镜 | 实际查询、来源、缺口补查 |
| 主动找反证 | 挑错员·赤狐，橙红/狐狸 | 例外、限制、反面材料 |
| 核验出处 | 验源官·阿金，金/证件；核证员·紫灯，紫/提灯 | 两位分别展示来源适用性和片段支持度 |
| 给出结论 | 档案官·墨墨，深绿/档案 | 已查明、未知项、停止原因 |

展开层为：本次在做什么 → 实际记录 → 为什么这样查。角色状态从事件产生，允许回到上一步；按查询 purpose 区分直接/反证/补查。计划、等待、未执行、降级、失败不能伪装完成。两种审查必须有分开的真实记录，不要求六个模型实例。

科学说明独立折叠，标明方法借鉴及限制，提供 FActScore、IRCoT、ALCE 的论文入口；不展示或虚构模型内部思维。卡片正文保留友好标题，专业方法在详情里解释。

统一实际中文字体（含说明、输入框、引文、按钮）；不可用删除说明替代字体修复。可点击区域有展开、hover、focus 提示；纯指标和面包屑不伪装按钮。目标宽度836px与1440px，无横向溢出和遮挡。

后续用户纠正：输入区不得保留A/B/C等固定测试题按钮；实际调查方向选项只有在问题存在实质歧义时才展示，不把无关演示题当作用户问题的可选方向。输入说明/隐私说明保持完整，并以浏览器实际字形确认字体，不能仅凭font-family声明验收。

## 3. 分工、素材与独立审查

主智能体负责集成、标准维护、真实验收与图片检查。素材子智能体负责所有图片生成、切图、透明处理，可用3×3素材图批量生成六个角色后裁切；最终资产必须在工作区，保留源图及角色映射，不强制精细复杂造型。主智能体不得自行生成替代图片。

素材验收：六角色在48/64px可辨认、颜色/道具不同、无裁头/残留其他格内容、无水印/乱码、透明通道真实、网页路径可访问。若工具不可用如实记录阻塞，不假称已生成，不静默切换收费API。

独立审查子智能体覆盖：证据门槛、开放问答/超时回归、事件真实性、旧报告兼容和前端可交互辨识。按严重程度提交文件/行号、触发条件、影响。主智能体修复阻塞项后复验；未解决项明示。

## 4. 阶段门槛与时间盒

| 阶段 | 时间 | 必须产出与通过条件 |
|---|---|---|
| S0 固定范围 | 0–5分 | 标准落盘、三道题固定、健康配置摘要；不得包含密钥 |
| S1 搜索闭环 | 5–25分 | 原子主张、开放问答、结构化答案、超时保留；相关离线回归通过；输出事件足以支持角色 |
| S2 角色与交互 | 25–43分 | 五卡六角色、两审查分离、真实状态、方法展开；素材检查和836/1440浏览器检查 |
| S3 联合验收 | 43–55分 | 全部相关离线检查及三次真实查询；保存JSON、截图、耗时/调用次数，独立审查 |
| S4 交付 | 55–60分 | 只修阻塞项；服务可打开；更新验收矩阵和限制；不得用历史成功覆盖本次失败 |

第43分钟冻结功能，之后只修阻塞问题。超时可削减装饰和说明篇幅；不可削减证据绑定、两种审查、真实状态与验收。所有门槛只有 PASS / FAIL / BLOCKED / NOT_RUN；不得把“写了代码”等同通过。

## 5. 精简验收写法与参考

每项记录：编号、前提→操作→可观察结果、证据路径、执行者、状态。关键项失败或未执行不能宣称全量通过。真实三题是演示验收，不是统计基准。

采用 Cucumber 的 Given/When/Then 场景写法，借鉴 NIST AI RMF MEASURE 对测试条件、结果、局限记录的要求；不引入新测试框架或合规流程。
