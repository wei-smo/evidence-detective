# 搜索智能体的方法、提示词与训练说明

## 当前版本实际做了什么

当前版本使用元宝 SearchPro 与部署者配置的 DeepSeek API，由自建 Python 调查控制器组织查询、阅读、两道审查、补查与证据绑定。项目没有执行模型权重的监督微调（SFT）、强化学习（RL）或检索器训练，没有训练检查点、LoRA 权重或可宣称的公开基准成绩。

开发对话中的“训练智能体”“教会智能体”等口语，实际对应需求澄清、研究讨论、系统提示词修改、调度逻辑改进和回归验证。以下资料按这些真实用途公开，不把讨论中的未来方案写成已完成训练。

## 已落实的工程机制

1. 原子主张：最多3条，保留原问题对象、时间、版本与条件；开放问答先搜索，再从材料形成待核验候选。
2. 迭代检索：直接查询、反证与缺口补查；优先核对已读积压材料，重复查询去重。
3. 来源适用性：分别核对实体、时间、条件与一手身份，不能只因域名看似权威就接受结论。
4. 片段支持度：FULL、PARTIAL、CONTRADICT、NONE、UNKNOWN；部分支持不能补齐未被证明的条件。
5. 引用归因：原文连续片段绑定主张、来源和位置，程序校验原文匹配及哈希；字面匹配不等于语义正确。
6. 结论门槛与状态：反证、冲突、原文、来源组、必要缺口与预算共同约束输出；服务失败与材料不足分别记录。

六个角色对应工作职责，来源适用性和支持度使用同一配置模型的不同调用，不代表六个独立模型互证。

## 可检查的系统提示词

实际使用的提示词与调用入口位于 [reasoning.py](../evidence_detective/reasoning.py)：

- `PLAN_SYSTEM`：问题类型、主张和查询规划。
- `CANDIDATE_SYSTEM`：从本次材料提取候选事实。
- `SOURCE_SYSTEM`：来源适用性。
- `ANALYSIS_SYSTEM`：原文支持度、冲突与补查建议。

程序门槛见 [engine.py](../evidence_detective/engine.py) 和 [provenance.py](../evidence_detective/provenance.py)。提示词公开不包含托管模型的隐藏内部思维。

## 研究依据与适配边界

| 研究 | 借鉴内容 | 当前边界 |
|---|---|---|
| [FActScore](https://aclanthology.org/2023.emnlp-main.741/) | 原子事实拆解 | 未实现论文标准评分流程 |
| [IRCoT](https://aclanthology.org/2023.acl-long.557/) | 检索与判断交替 | 工程适配，未复现逐句CoT算法 |
| [ALCE](https://aclanthology.org/2023.emnlp-main.398/) | 回答与引用质量分别检查 | 未运行正式ALCE评测 |
| [TREC RAG](https://trec.nist.gov/pubs/trec34/papers/Overview_rag.pdf) | 支持度与信息单元覆盖 | 采用分级支持思想，未建立完整nugget金标准 |
| [STORM](https://github.com/stanford-oval/storm) | 多角度提问与追问 | 架构参考，未接入完整框架 |
| [BrowseComp](https://openai.com/index/browsecomp/) / [BrowseComp-Plus](https://texttron.github.io/BrowseComp-Plus/) | 难找易核验、固定语料与正负例 | 调研参考，没有本项目正式跑分 |
| [LiveBrowseComp](https://arxiv.org/abs/2605.28721) | 检验对新外部证据的依赖 | 尚未执行闭卷、删证据等对照实验 |

## 开发对话的用途

[对话归档](conversations/README.md) 包含需求、研究讨论、故障诊断及修复说明的可见用户/助手消息。历史消息反映当时判断，可能包含后来纠正的说法；应结合日期和最新源码阅读。对话不是经过逐条正确性标注的训练集，助手自评不能充当事实金标准。

如未来开展真正的权重训练，需要另行构建证据核验过的轨迹、正确/错误动作标注与来源支持标签，按实体/时间/来源去重划分训练和测试集，再选可训练模型执行SFT或交互RL。该路线仅为未来方案，不属于本次发布成果。
